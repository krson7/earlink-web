# 기기 연결 공유 API

한 휴대폰이 EarLink에 BLE로 연결하고 나머지 참여자는 모드를 선택해 입장한다. 다른 휴대폰의 연결 상태는 FastAPI가 공유한다. 구현은 [`backend/device_presence_router.py`](../backend/device_presence_router.py), 설치는 [backend 안내](../backend/README.md)를 참고한다.

브라우저는 웹 주소의 `/api/backend/rooms/device`를 호출하며 Next.js가 FastAPI의 `/rooms/device`로 전달한다. HTTP 요청을 휴대폰에서 백엔드로 직접 보내지 않으므로 휴대폰의 localhost 주소·CORS·HTTP 혼합 콘텐츠 문제를 피한다. 읽기와 프록시 응답에는 `Cache-Control: no-store`를 지정한다.

## 조회

`GET /rooms/device`는 다음 JSON을 반환한다.

```json
{ "connected": true, "serial_number": "EL-0427" }
```

연결이 없으면 `connected: false`, `serial_number: null`이다. 시리얼 특성이 없는 펌웨어는 연결되어 있어도 시리얼이 `null`이다. 연결하지 않은 브라우저는 3초마다 조회하며 포커스·화면 복귀 시에도 갱신한다.

첫 조회 중에는 연결 확인 화면에서 잠시 기다린다. 연결이 확인되면 페어링 화면을 띄우지 않는다. 대기 중 다른 휴대폰이 연결하면 다음 조회에서 페어링 화면을 닫는다. 연결이 없거나 조회가 실패하면 연결 안내를 표시하지만, **페어링 없이 대화 참여** 또는 닫기를 누르면 모드를 선택해 입장할 수 있다. 안내를 닫은 뒤에는 조회가 반복되어도 자동으로 다시 열지 않는다. Bluetooth 연결은 대화방 입장 조건이 아니며, 미지원 브라우저도 대화할 수 있다. ESP의 BLE 연결은 한 휴대폰이 맡는다.

조회 실패 시 연결 상태 공유 오류를 표시하고 3초마다 재시도한다. 페어링을 건너뛰어도 실제 기기가 연결되었다고 표시하거나 연결 상태를 서버에 보고하지 않는다.

## 연결 담당자의 보고

`PUT /rooms/device` 요청:

```json
{
  "connected": true,
  "serial_number": "EL-0427",
  "owner_id": "브라우저 연결 세션의 임의 UUID"
}
```

성공 응답은 본문 없는 `204`다. 실제 GATT 초기화를 마친 후에만 연결을 보고한다. 연결 중에는 성공 후 20초마다 갱신하며 실패 시 3초 후 재시도한다. 포커스·화면 복귀·네트워크 복구 시에는 즉시 갱신한다. 보고 실패도 사용자에게 표시한다. 연결 해제·화면 종료 시에는 `connected: false`를 보낸다. 화면 종료 보고에는 `keepalive`를 사용하지만 전달을 보장하지 않으므로 마지막 갱신에서 **60초 후** 서버가 상태를 만료시킨다.

현재 연결 소유자의 `owner_id`만 갱신·해제할 수 있다. 다른 소유자의 해제는 무시하고, 만료되지 않은 연결을 덮어쓰려 하면 `409`를 반환한다. 소유자 토큰은 조회 응답에 포함하지 않는다. 브라우저는 연결·해제 요청을 순서대로 보내므로 이전 해제가 새 연결 보고보다 늦게 반영되지 않는다.

현재 고정 대화방과 기존 채팅 서버의 단일 worker 구성에 맞춘 메모리 상태다. 다중 worker·다중 서버에서는 채팅과 기기 상태를 함께 공용 저장소로 이전해야 한다. 방이 여러 개가 되면 기기 상태도 방 단위로 분리해야 한다.

## 회귀 검사

격리 백엔드(`tests/backend/live_chat_server.py`)와 웹 서버를 실행한 뒤 `npm run test:presence:browser`로 검사한다. 웹 주소는 `EARLINK_TEST_URL`(기본 `http://127.0.0.1:3100`), 격리 API 주소는 `EARLINK_TEST_API_URL`(기본 `http://127.0.0.1:3180`)로 지정한다. 검사 시작·종료 시 테스트 서버의 연결 상태만 초기화한다.

실제 HTTP·WebSocket과 브라우저 3개를 사용해 첫 연결 보고의 일시 실패·3초 재시도, 대기 중인 두 참여자의 자동 안내 닫힘, 연결 담당자 화면 복귀 시 상태 복구, 페어링 한 번으로 3인 메시지 중계를 확인한다. BLE는 테스트 fixture를 사용한다. `npm run test:bluetooth:browser`에서는 API 미설치·Bluetooth 미지원 상황의 페어링 없는 입장과 닫은 안내의 재표시 방지를 확인한다.
