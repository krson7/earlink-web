# 9버튼 한글 점자 키보드

기존 웹→ESP32 3칸 점자 출력은 유지하고, 같은 GATT 서비스에 입력 전용 특성을 추가한다. 펌웨어와 웹을 모두 업데이트해야 한다. **실물 버튼·BLE·배포 사이트를 통한 종단 간 시험은 아직 별도 확인이 필요하다.**

## 연결과 조작

사용자가 지정한 실제 왼쪽→오른쪽 순서:

| GPIO | 14 | 21 | 27 | 26 | 13 | 33 | 12 | 32 | 25 |
|---|---|---|---|---|---|---|---|---|---|
| 기능 | 전송 | 3점 | 2점 | 1점 | 띄어쓰기 | 4점 | 5점 | 6점 | 지우기 |

각 스위치는 GPIO와 GND 사이에 연결한다. `INPUT_PULLUP`, 눌림=LOW, 공통 GND를 사용한다. 별도 키보드 컨트롤러가 신호를 구동하는 회로라면 그 회로의 출력 극성과 전압부터 확인한다. 기존 DATA/LATCH/CLOCK GPIO 16/17/18과 겹치지 않는다. 일반 ESP32의 GPIO12는 부팅 스트랩 핀이므로 부팅 순간 외부 회로가 HIGH로 강제하지 않아야 한다. [Espressif 핀 문서](https://docs.espressif.com/projects/arduino-esp32/en/latest/boards/ESP32-DevKitC-1.html#strapping-pins)

- 점 키의 누름을 누적하고 **모두 떼면 한 칸**을 입력한다. 하나를 유지하면서 다른 점을 추가하는 순차 누름도 가능하다. 하나씩 완전히 떼면서 누르면 각각 별도 칸이다.
- 스위치마다 20ms 디바운스를 적용한다. 부팅 때 누른 키는 모두 떼기 전까지 무시한다.
- 띄어쓰기는 빈 점자 칸 하나다. 지우기는 마지막 점자 한 칸을 제거한다. 0.8초 이상 누른 지우기는 **키를 뗄 때** 전체 삭제한다. 이후 한글을 다시 조합한다.
- 점+기능 키, 기능 키 여러 개의 조합은 해당 누름 전체를 무시하고 시리얼에 로그만 남긴다. 길게 누르기와 섞인 입력을 함께 판단하기 위해 기능도 모든 키를 뗀 뒤 실행한다.
- 입력은 ESP의 RAM에 최대 512칸 저장한다. BLE가 끊겨도 유지하며 재연결 시 웹에 동기화한다. **전원 차단·재부팅에는 보존하지 않는다.** 키 입력으로 솔레노이드를 구동하지 않는다.

## 웹 사용

시각장애 모드로 대화방에 입장하고 EarLink를 연결하면 ‘점자 키보드로 작성’ 영역에 한글을 표시한다. 기기의 전송 키 또는 웹 전송 버튼을 누르면 기존 채팅 전송 함수를 사용한다. 기본 자모·된소리·복합 모음·겹받침, ㅏ 생략, 14개 모음+받침 약자, 것/껏, 성 계열 및 7개 약어를 지원한다. 한글 규칙은 [2024 개정 한국 점자 규정](https://www.korean.go.kr/front/etcData/etcDataView.do?etc_seq=710&mn_id=207)과 기존 `BrailleRules.h`를 기준으로 한다.

예시(띄어 쓴 숫자 묶음 각각을 한 번의 점 키 누름으로 입력):

| 작성할 글 | 칸별 점 번호 |
|---|---|
| 한글 | `245 / 25 / 4 / 2346` 또는 풀어쓰기 `245 / 126 / 25 / 4 / 2346` |
| 가나다 | `1246 / 14 / 24` |
| 안녕 | `126 / 25 / 14 / 12456` |
| 안녕하세요 | `126 / 25 / 14 / 12456 / 245 / 6 / 1345 / 346` |

입력 도중에는 뒤의 칸에 따라 앞의 자모가 다시 조합된다. 끝나지 않은 자음이나 해석하지 못한 칸은 화면에 남기고 전송을 막는다. **이번 입력기는 한글 중심이며 숫자·영문·문장부호·단독 자모 표기 전체는 지원하지 않는다.** 점형이 겹치는 부호는 현재 한글 문법으로 해석한다. 기존 출력기가 그 문자를 지원하는지와 입력기 지원 범위는 별개다.

## 보존과 전송 확인

웹은 2초마다 채팅 준비 상태와 동기화 요청을 보낸다. ESP는 BLE 연결 및 최근 6초 이내의 웹 준비 상태를 확인한 뒤 전송 요청을 만든다. 채팅이 끊겨 있거나 준비되지 않았으면 입력을 비우지 않는다. 전송할 원본 점자 칸은 별도로 고정하고 요청 ID를 부여한다.

웹은 해당 요청을 한글로 해석한 뒤 기존 `sendMessage()`가 `true`를 반환하면 성공 ACK를 보낸다. **이 성공은 WebSocket 송신 API가 받아들였다는 뜻이며, 서버 저장·상대방 수신 완료 확인은 아니다.** 현재 서버 프로토콜에는 요청 ID를 동반한 수신 확인이 없다.

ESP는 성공 ACK를 받은 뒤 해당 입력 접두부만 제거한다. 전송 중 추가한 칸은 남는다. 원본 접두부를 지우거나 수정했다면 현재 입력을 그대로 보존한다. 실패 ACK는 입력을 지우지 않는다. 확인이 30초 늦어져도 요청 ID와 입력을 유지한다. 연결을 복구하면 같은 요청에 대한 확인을 이어간다.

웹은 처리 결과를 기기 ID·부팅 난수·요청 ID로 기억해 중복 알림을 다시 채팅에 보내지 않고 ACK만 재전달한다. 같은 탭의 `sessionStorage`에도 최근 128건의 결과만 저장한다(메시지 내용 미저장). 탭을 닫거나 저장소를 지운 이후 및 다른 탭/브라우저 사이의 전역 중복 방지는 보장하지 않는다. 저장소 사용이 막혀도 같은 페이지 내에서는 메모리로 중복을 방지한다.

## 입력 전용 BLE 규격 v1

서비스 `8f3a0001-7c3b-4b8a-9f52-123456789abc` 안에 `8f3a0004-7c3b-4b8a-9f52-123456789abc`를 추가한다. 속성은 WRITE + NOTIFY, CCCD 사용. 기존 TEXT/STATUS UUID와 16바이트 STATUS 형식은 바꾸지 않는다. 구 펌웨어 연결 시 웹의 점자 출력은 계속 사용하고 키보드 업데이트 안내를 표시한다. [Web Bluetooth GATT 알림](https://developer.chrome.com/docs/capabilities/bluetooth)

모든 정수는 little-endian. dot1=bit0, dot6=bit5, 공백=0. 전송 패킷은 20바이트 이하, 알림 간격은 최소 12ms다.

| ESP→웹 | 바이트 |
|---|---|
| BEGIN (19바이트) | `version=1, op=1, bootId:u32, revision:u32, requestId:u32, draftCount:u16, pendingCount:u16, feedback:u8` |
| DATA (9~20바이트) | `version=1, op=2, revision:u32, offset:u16, cells[1..12]` |
| END (6바이트) | `version=1, op=3, revision:u32` |

DATA의 전체 셀 열은 `현재 작성 칸 + 전송 대기 원본 칸`이다. 요청이 없으면 requestId/pendingCount는 0이다. BEGIN~END는 고정된 스냅샷으로 끝까지 전송하고, 도중 입력 변경은 다음 스냅샷에 반영한다. 웹은 길이·순서·리비전·칸 범위를 검사하며 END가 올 때만 화면과 전송 요청을 갱신한다. 알림 누락은 주기 동기화로 복구한다.

| 웹→ESP | 바이트 |
|---|---|
| 동기화 요청 | `1, 1` |
| 처리 결과 | `1, 2, requestId:u32, accepted:u8(0 또는 1)` |
| 채팅 준비 상태 | `1, 3, ready:u8(0 또는 1)` |
| 웹 버튼의 전송 요청 | `1, 4` |

feedback: 0=없음, 1=입력 가득 참, 2=연결/준비 안 됨, 3=확인 지연, 4=웹 전송 거절, 5=빈 입력. 이 코드들은 기존 출력 상태/ACK와 섞이지 않는다. 웹 GATT 쓰기는 기존 출력·제어와 같은 큐에서 순차 실행한다.

## 검증과 장치 적용

```powershell
npm.cmd run test:earlink
python firmware/tests/run_tests.py
node node_modules/typescript/bin/tsc --noEmit --incremental false
npm.cmd run build
arduino-cli compile --fqbn esp32:esp32:esp32 --build-path .firmware-build/esp32 firmware/earlink
```

네이티브 키보드 검사에는 63개 점 조합, 점+기능 혼합 189가지, 순차 누름, 기능 키 중복, 디바운스, 799/800ms 경계, 타이머 순환, 오프라인 입력 보존, ACK 중복/실패/지연, 전송 중 편집과 512칸 상한을 포함한다. 웹 검사는 독립된 공식 한글 예시 229개, 기본 모음/겹받침, 패킷 누락·순서·범위, 중복 전송·재연결·저장소 오류를 포함한다. C++가 출력한 실제 키보드 프레임을 웹 코드에서 조립하고 채팅 콜백까지 실행하는 교차 검사도 실행한다.

최신 `firmware/earlink` 폴더 전체를 ESP에 업로드하고 웹을 재배포한 뒤 연결을 해제·재연결한다. 확인 순서는 `한글 입력 → 짧은 삭제 → 긴 삭제 → 띄어쓰기 → 전송 → 채팅 연결 차단 시 입력 보존 → BLE 재연결 동기화 → 상대 메시지의 기존 점자 출력`이다. 이 실물 검사는 자동 검사나 컴파일 성공으로 대체되지 않는다.
