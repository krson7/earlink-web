# 한국 점자 규정 2024 적용 근거와 범위

기준은 국립국어원 발행 **문화체육관광부고시 제2024-0005호**이다. 규정 전체의 구현 완료나 점역 전문 검수를 선언하지 않는다. 이 문서의 조항 번호는 별도 표시가 없는 한 **한글 점자**의 번호다.

## 약어·약자 적용 순서

1. UTF-8을 검증하고 현대 한글 L+V(+T)를 완성형으로 분석한다.
2. 단어 경계에서만 제18항의 약어를 찾는다. 앞에 한글·로마자·숫자·자모가 붙으면 약어로 시작하지 않는다. 문장부호·공백 뒤에는 다시 시작할 수 있다.
3. 모음 연쇄 구분표를 판단한다.
4. 것/껏, ㅏ 약자와 제14항 예외, 제17항 성 계열, 제15항 모음+받침 약자를 판정한다.
5. 약자를 적용한 부분 이외의 자모·남은 받침만 출력한다.

문서의 줄바꿈은 아래의 디스플레이 정책과 별개다. 소프트웨어 페이지 경계를 문자 문서의 줄 끝으로 간주하지 않는다.

## 미구현·미검증 사항

**일반 영문 UEB 묶음약자/단어약자 엔진은 미구현이다.** 제32·37항을 충족했다고 선언하지 않는다. `verifiedRomanWord()`의 제한된 어휘와 단일 로마자만 받아들인다. 예를 들어 `Hello`, `HELLO`, `MP3`는 테스트하지만 `school`, `Table of Contents`, 임의의 새 영어 단어는 `UNVERIFIED.K32.K37.UEB-word`로 보고하여 장치 출력에서 거부한다. 일반 영문을 모두 풀어 써서 정확한 점역인 것처럼 출력하지 않는다. 목록의 어휘도 모든 문장 문맥을 인증한 것은 아니다.

이 제한은 기존 MVP보다 영문 입력 허용 범위를 줄인다. 정확성을 우선하기 위한 **명시적 제한이며, 사용자가 요청한 전체 영문 지원이 완료된 상태가 아니다.** 추후 일반 UEB 엔진과 독립 검증 말뭉치를 추가해야 한다.

아래도 완료로 표시하지 않는다.

- 단독 ㄸ·ㅃ·ㅉ: 해당 받침형을 임의로 만들지 않고 미지원으로 보고한다. 현대 음절 안의 된소리 처리는 별도로 지원한다.
- 제19~27항 옛한글, 제30~31항 그리스 문자, 제38항 IPA, 제39항 로마자 주 문장의 한글 구획.
- 수학식 의미 분석, 수식의 `-`와 전화번호 붙임표의 의미 판별, 시각적 분수·첨자·강조·서식·글머리표·숨김표 전체. ASCII `-`는 붙임표로 취급한다. 수식 점역기라고 간주하면 안 된다.
- 단위와 화폐의 모든 유니코드 호환 문자, 복잡한 URL·이메일과 제74항 컴퓨터 점자 전체.
- 제49항 붙임의 단독 문장부호 설명 주석 전체, 제51항 쌍점의 대비/열거 의미 판정. **단독 물음표의 구분표·‘물음표’ 점역자 주는 34쪽 실제 예에 따라 구현했다.** 혼동되는 단독 느낌표·쉼표·마침표는 `UNVERIFIED.K49.standalone-punctuation`으로 거부한다. 한글에 붙은 쌍점의 의미가 불명확하면 `UNVERIFIED.K51.semantic-spacing`으로 거부한다. 숫자 사이 쌍점과 이미 뒤가 띄어진 쌍점은 처리한다.
- 따옴표의 문학적·중첩 의미와 발음 표기용 대괄호의 모든 문맥. ASCII `'`/`"`는 기본적으로 여닫는 인용부호의 쌍으로 해석하며, 숫자 앞 `'`는 아포스트로피다. 구분된 유니코드 인용부호 입력을 권장한다.
- `…` 1~2개, `.` 3개/6개 이외의 줄임표 개수는 미검증으로 거부한다.
- 문장부호 표의 점형이 존재해도 의미·띄어쓰기까지 자동 해결한 것으로 간주하지 않는다. 특히 별표의 주석/참고표 의미, 표시 서식은 입력에 없는 정보를 추론하지 않는다.
- 논리적 점역의 전문 촉독 검수, 실기 BLE·핀·점 위치·정격·발열·전원·연속 통전 시험.

## 디스플레이 정책과 규정 검증의 구분

- 공백은 빈 셀 1개다. 탭/LF/CR도 빈 셀 1개, CRLF는 합쳐서 1개로 취급한다. 탭 폭이나 문서 줄 길이를 재현하지 않는다.
- 3칸 페이지는 연속 점자 스트림을 잠시 나누어 보이는 창이다. 제11·12·14항의 종이 줄바꿈 예외, 제42항의 숫자 줄 연결표, 문장부호 금칙 처리를 페이지마다 넣지 않는다.
- U+2800~U+283F 원시 점자 입력은 기존 장치 호환용 직접 셀 입력이다. 묵자에 인쇄된 점형을 표현하는 제67항 점역과는 다르며 규정 검증 PASS로 분류하지 않는다.
- NFD 조합, 원시 셀, 표시 줄바꿈 정책은 회귀 검사를 통과해도 규정 판정은 **UNVERIFIED**로 둔다.

## 오류와 메모리

`Translation`은 기존의 `cells`, `uint16_t unsupported` 두 필드를 그대로 유지한다. 미지원 문자·잘못된 UTF-8·코드가 미검증으로 판정하는 규칙에서는 `unsupported`가 증가한다. 임의의 물음표나 대체 점형은 넣지 않는다. `cells`에는 부분 변환이 있을 수 있으므로 **호출자는 unsupported가 0일 때만 출력해야 한다.** 실제 BLE 통합과 Pager는 이 조건을 강제한다.

점역 오류는 기존 `BAD_PACKET=2`, 저장 공간 부족은 기존 `QUEUE_FULL=5`로 응답한다. 새 UUID·프레임·결과 코드는 만들지 않았다. 거부된 메시지의 문자와 0부터 시작하는 바이트/스칼라 위치, 사유를 시리얼에 최대 32건 기록하고 총 개수도 출력한다. 기존 STATUS 오프셋 12는 **현재 표시 중인 메시지**의 unsupported라는 의미를 그대로 유지한다. 거부된 다른 메시지의 개수로 덮어쓰지 않는다. 따라서 새 오류의 상세 내용은 시리얼 로그에서 확인해야 한다.

측정 패스와 출력 패스를 분리하여 셀 수만큼 정확히 한 번 reserve한다. 전체 디코딩 버퍼나 자모 문자열 배열을 입력 크기만큼 만들지 않는다. 수신 4096바이트, 변환 24592셀, 현재+대기 32768셀 상한을 검사한다. 대기 메시지는 기존과 동일하게 3개다. 수신 버퍼는 reset 후 최대 4096바이트 capacity를 재사용한다. ESP32는 출력 벡터 생성 전 가용 힙과 최대 연속 블록을 확인하고 BLE용 여유 16384바이트를 남긴다. 이 검사는 모든 시스템 할당 실패나 실제 장치 정격을 보증하지 않는다.

2026-11-13 장문 검사에서 `? ` 2048회 반복 입력이 24592셀에서 조용히 잘리는 오류를 발견해 수정했다. 단독 문장부호의 설명 주석 때문에 입력 1바이트당 6셀 이하라는 가정은 성립하지 않는다. 지금은 셀 상한을 넘는 최초 위치에서 `LIMIT.output-cells`를 한 번 기록하고 `unsupported`를 올린다. BLE와 Pager가 메시지 전체를 거부하므로 잘린 결과가 정상 출력되지 않는다. 상한에 정확히 맞는 경우와 한 셀 초과하는 경우도 회귀 검사한다.

## 검증 방식

`tests/cases_2024.py`의 정답은 공식 점자 표·예시를 전사하거나 조항으로 직접 조합한 고정 데이터다. 구현의 변환 결과를 정답으로 저장하지 않는다. PDF 글꼴의 Braille ASCII를 독립적인 점 번호 표로 해석하며 구현의 테이블을 읽지 않는다.

추가로 `tools/check_official_source.py`가 해시를 고정한 공식 PDF의 실제 `HSBRL` 글꼴을 읽어, 공식 표·예시에서 전사한 **312건의 비어 있지 않은 점형열이 해당 출처 쪽에 존재함**을 확인했다. [원문 대조 기록](validation/official-source-audit.json)을 제공한다. 이 기계적 검사는 공백·정확한 단어 정렬·의미·규칙 판정까지 검증하지 않으며 수작업 대조와 별개다. 선택적 원문 재검사에만 `pypdf`가 필요하다. 일반 PC 테스트에는 필요 없다.

`tests/official_words_2024.json`에는 같은 행의 낱말과 점자 글꼴을 짝지어 확인한 229개 예시의 좌표를 고정했다. 이 중 기존 입력과 겹치지 않는 161개를 고정 정답 테스트에 추가했다. 새 추출기는 검토용 후보만 생성하며 정답 파일을 자동으로 덮어쓰지 않는다. `온표`, `때에는`, `의약자`는 예문이 아닌 조문 설명이므로 검토 때 제외했다.

- `official-table`: 공식 표의 해당 항목.
- `official-example`: 공식 원문의 해당 낱말/문장.
- `official-example-fragment`: 공식 예문의 발음 표기 등 일부를 그대로 추출한 입력.
- `official-coordinate-example`: 원본 PDF의 같은 행 낱말/점자 글꼴 대응과 좌표를 확인한 예시.
- `manual-rule-composition`: 원문에 없는 입력을 명시한 조항으로 수작업 조합한 정답. 원문 예문 자체와의 직접 일치라고 표시하지 않는다.
- `application-policy`, `unsupported/unverified`: 규정 판정 UNVERIFIED.

PASS는 해당 고정 입력의 대조 결과다. 기존의 현대 음절 11172자 순회는 범위·버퍼 검사다. 추가로 Python의 Unicode NFD와 조항별 점형 사실을 사용하는 별도 기대값 생성기를 작성해 모든 음절과 인접 124813584쌍을 일반/ASAN 빌드에서 대조했다. **이 생성기도 같은 규정을 해석해 작성한 코드이므로, 독립적인 전문 점역기나 사람의 검수를 대체하지 않는다.** 직접 공식 표·예시와 대조한 312건과 규칙으로 생성한 전수 검사는 별도로 보고한다. 원시 3셀 조합 262144개 비교 역시 이전 드라이버의 전송 바이트 호환성 검사다.
