# EarLink 3칸 점자 출력 MVP

사용자가 정한 하드웨어 조건: ESP32 Dev Module, 5V 3A 전원, 6점 × 3칸(18개 솔레노이드), DATA/CLOCK/LATCH 방식의 주영소프트 예제 PCB. 74HC595·L293D는 PCB 분석상의 추정이며 이 구현에서 확정한 부품명은 아니다.

## 실행 흐름

```text
기존 FastAPI 채팅
 → VISUAL 모드에서 새 상대방 메시지 수신
 → 웹에서 NFC 정규화 후 UTF-8 바이트 분할
 → ESP32에서 전체 메시지 재조립
 → ESP32에서 기본 점자 셀 배열로 변환
 → 점자 셀 3개씩 출력
 → 남은 메시지를 수신 순서대로 처리
```

채팅 UI, 서버 요청/응답, 지문자 인식 경로는 유지했다. 기기 이름과 기존 Service/Text UUID도 유지하되, Text characteristic의 내용은 **v1 전송 프레임**으로 바뀌었다. 기존 원문 단일 Write 펌웨어와 호환되지 않으므로 웹과 이 펌웨어를 함께 사용한다. 새로운 상태/제어 characteristic이 없는 기기에는 웹이 업로드 안내를 표시한다.

## 글자 크기와 길이

장치의 물리적인 점 크기·간격은 고정이다. 웹의 글꼴 크기는 점자 출력에 영향을 주지 않는다. 분할 기준은 원문 3글자가 아니라 **변환된 점자 3셀**이다.

기본 풀어쓰기 모드의 예:

| 원문 | 점자 셀 수 | 3칸 장치 출력 |
|---|---:|---|
| 아 | 1 | 모음 1셀 + 빈 칸 2개 |
| 한 | 3 | ㅎ / ㅏ / 받침 ㄴ |
| 한글 | 6 | 2페이지 |
| 꿇 | 5 | 된소리표·ㄱ·ㅜ / 받침 ㄹ·ㅎ·빈 칸 |
| 123 | 4 | 수표·1·2 / 3·빈 칸·빈 칸 |

한 음절이나 단어의 점자 표현이 페이지 사이에 나뉠 수 있다. 이 MVP는 연속된 점자 스트림을 3셀씩 보여주며 종이 문서의 줄바꿈·연결표 규칙을 적용하지 않는다.

기본 자동 출력은 페이지당 3초, 페이지 사이 전체 OFF 250ms다. 웹에서 1/2/3/5/10초를 선택할 수 있다. 이전/다음을 누르면 직접 넘김으로 전환하며, 자동 넘기기로 복귀할 수 있다. 직접 넘김 상태에서 10초가 지나면 출력은 OFF되지만 현재 페이지 데이터는 보존한다. 이전 또는 자동 넘기기로 다시 표시한다. 이 시간은 소프트웨어 기본값이지 코일의 검증된 연속 통전 정격을 의미하지 않는다.

마지막 페이지의 부족한 칸은 0으로 채운다. 메시지가 끝나거나 출력 지우기/연결 해제가 발생하면 실제 레지스터에 0을 쓰고 latch한다. 최대 현재 1개 + 대기 3개까지 저장하며, 큐가 가득 차면 ACK에 실패 코드를 반환한다. 웹에 표시되는 실패 메시지는 사용자가 다시 보낼 수 있다. 자동 재전송은 하지 않는다. 수신 확인이 유실된 뒤 수동 재전송하면 중복 출력될 수 있다.

## 파일

- `earlink/earlink.ino`: BLE 이벤트, 상태 알림, 주영소프트 방식 shiftOut 출력, 비차단 loop.
- `earlink/Config.h`: 핀, 점→비트 대응, 셀 순서, 출력/시간 설정.
- `earlink/BrailleText.h`: 기본 풀어쓰기 변환기.
- `earlink/Protocol.h`: 순서·길이를 검사하는 UTF-8 프레임 재조립.
- `earlink/Pager.h`: 3셀 페이지, FIFO, 타이머, 직접/자동 넘김.
- `tests/core_test.cpp`: 실제 펌웨어 핵심 코드를 PC에서 실행하는 테스트.

## 업로드와 점 위치 확인

1. Arduino IDE에서 `earlink/earlink.ino`를 연다. ESP32 보드 패키지의 **ESP32 Dev Module**을 선택한다. Arduino-ESP32 3.3.12에서 컴파일 확인했다. 별도 BLE 라이브러리를 추가하지 않고 해당 코어에 포함된 BLE를 사용한다.
2. `Config.h`에서 실제 배선을 확인한다. 현재 **DATA=2, LATCH=3, CLOCK=4는 미확인 임시값**이다. 사용자가 GPIO 2·3·4를 제시했지만 역할 순서는 아직 확인되지 않았다. 일반 ESP32 variant에서 GPIO3은 기본 UART RX와도 겹친다. 이 예제는 시리얼 입력 명령을 사용하지 않는다.
3. 현재 `OUTPUT_ENABLED=false`로 되어 있다. 이 상태에서도 BLE 수신·점자 변환·페이지 상태를 확인할 수 있으며 GPIO 출력은 하지 않는다. 핀 역할과 점 대응을 확인한 다음 `true`로 변경하고 다시 컴파일/업로드한다. 전원을 바꾸라는 요구가 아니라 미확인 배선으로 출력하지 않도록 분리한 설정이다.
4. `DOT_BITS`의 첫 값은 점1, 다음은 점2…점6에 해당하는 레지스터 비트다. 기본값 0~5 역시 PCB의 실제 점 대응을 확인해야 한다. 셀 전송 순서 역전과 `LSBFIRST`는 사용자가 제공한 예제를 따른다.
5. 실제 보드 포트를 선택해 업로드한다. 이 작업에서는 보드 업로드나 솔레노이드 구동을 실행하지 않았다.
6. 웹에서 VISUAL 모드에 입장하고 EarLink를 연결한다. 다른 참가자는 STANDARD 모드로 같은 방에 들어가 **연결 이후** 메시지를 보낸다. 본인 메시지와 연결 이전 메시지는 기존 정책대로 기기에 전달하지 않는다.
7. 점 위치를 확인할 때 아래 점자 유니코드 문자열을 상대방 채팅에서 보낼 수 있다. 빈 점자 셀 `⠀`은 일반 공백과 다르며 trim으로 삭제되지 않는다.

```text
⠁⠀⠀  첫 번째 셀의 점1
⠀⠁⠀  두 번째 셀의 점1
⠀⠀⠁  세 번째 셀의 점1
⠂⠀⠀  첫 번째 셀의 점2
⠄⠀⠀  첫 번째 셀의 점3
⠈⠀⠀  첫 번째 셀의 점4
⠐⠀⠀  첫 번째 셀의 점5
⠠⠀⠀  첫 번째 셀의 점6
```

위 문자열에서 설명을 제외한 점자 문자 3개만 전송한다. 점 배열은 읽는 방향에서 `1 4 / 2 5 / 3 6`이다. 실제 점이 다르면 `DOT_BITS`를 바꾸며, 왼쪽/오른쪽 셀이 뒤집히면 `REVERSE_CELL_ORDER`를 바꾼다.

## 변환 범위와 한계

이번 변환기는 **MVP 기본 풀어쓰기**다. 정식 한국 점자 규정 전체나 완전한 UEB 점역을 구현했다고 간주하지 않는다.

- 현대 완성형 한글 11,172자: 초성·중성·종성으로 풀어 적는다. 초성 ㅇ은 생략하며 된소리, 복합모음, 겹받침을 처리한다. 모음 뒤 예, 야/와/우/워 뒤 애의 구분표를 넣는다.
- 영문 A–Z/a–z: 외국 문자 시작/종료와 개별 대문자 표를 사용한 기본 알파벳 표기.
- 숫자 0–9: 숫자 묶음 앞 수표. 뒤에 한글/영문이 바로 이어지면 분리용 빈 셀을 넣는다.
- 공백/줄바꿈, `. , ? ! -`, 6점 점자 유니코드 U+2800–U+283F 지원.
- 약자·약어, 일반 점역의 ㅏ 생략, 독립 자모, 옛한글, 수학식, 소수점 숫자 문맥, 복합 문장부호, URL·외국어 혼합의 전체 규정은 미구현이다.
- 미지원 문자와 잘못된 UTF-8은 물음표 셀로 대체하고 개수를 상태로 알린다. 원문 메시지는 채팅에 그대로 남는다.
- 브라우저에서 NFC로 정규화하므로 정상적인 조합형 한글은 완성형으로 전송한다. 독립 ㄱ, ㅏ와 같은 호환 자모는 현재 미지원이다.

참조 자료: [국립국어원 한국 점자 규정 안내](https://www.korean.go.kr/front/page/pageView.do?mn_id=206&page_id=P000303), [Liblouis 기본 한글 점형](https://github.com/liblouis/liblouis/blob/master/tables/ko-chars.cti), [Espressif BLE Write 예제](https://github.com/espressif/arduino-esp32/blob/master/libraries/BLE/examples/Write/Write.ino). 점형 사실을 확인해 구현했으며 Liblouis 번역 엔진이나 표 파일을 프로젝트에 포함하지 않았다. 점역 품질과 실제 촉독은 별도 검증 대상이다.

## BLE v1 규격

기기 이름 `EarLink`, Service `8f3a0001-7c3b-4b8a-9f52-123456789abc`.

### Text: `8f3a0002-7c3b-4b8a-9f52-123456789abc` / Write with response

모든 정수는 little-endian. 모든 패킷은 최대 20바이트. UTF-8 메시지는 최대 4096바이트.

| 프레임 | 바이트 |
|---|---|
| BEGIN | `45 4C 01 01 id:u16 totalBytes:u16` |
| DATA | `45 4C 01 02 id:u16 byteOffset:u16 payload:1..12bytes` |
| COMMIT | `45 4C 01 03 id:u16` |

부분 UTF-8은 해석하지 않고 COMMIT에서 길이를 확인한 뒤 변환한다. 오프셋·ID가 맞지 않으면 해당 조립을 폐기한다. 10초 동안 후속 데이터가 없으면 조립을 취소한다. GATT Write 성공만으로 수신 완료로 간주하지 않고 별도 메시지 ACK를 기다린다.

### Status/control: `8f3a0003-7c3b-4b8a-9f52-123456789abc` / Read + Write + Notify

16바이트 상태:

| 오프셋 | 내용 |
|---:|---|
| 0 | 버전 1 |
| 1 | flags: bit0 메시지 활성, bit1 자동, bit2 GPIO 출력 설정, bit3 현재 셀 표시 |
| 2–3 | 마지막 수신 처리 메시지 ID |
| 4 | 결과: 0 없음, 1 수신 큐 등록, 2 형식 오류, 3 크기 초과, 4 순서/길이 오류, 5 큐 가득 참, 6 수신 시간 초과 |
| 5 | 대기 메시지 수 |
| 6–7 | 현재 출력 메시지 ID |
| 8–9 | 현재 페이지(1부터, 비활성 0) |
| 10–11 | 전체 페이지 수 |
| 12–13 | 현재 메시지의 미지원 문자 수 |
| 14–15 | 자동 페이지 표시 시간(ms) |

ACK=1은 메시지 변환 및 출력 큐 등록 완료이며, 솔레노이드가 물리적으로 움직였다는 센서 확인은 아니다.

제어 Write는 `[1, command]`: 1 다음, 2 이전, 3 전체 지우기, 4 직접 넘김, 5 자동 넘김. 표시 시간 설정은 `[1, 6, milliseconds:u16]`이며 1000~10000 범위다. 브라우저는 메시지와 제어 명령의 GATT 쓰기를 한 큐에서 직렬화한다.

## 검증 명령

```powershell
npm.cmd run test:earlink
node node_modules/typescript/bin/tsc --noEmit --incremental false
```

Node 22.18+ 또는 24에서 추가 테스트 의존성 없이 TypeScript를 실행한다. Node의 MODULE_TYPELESS_PACKAGE_JSON 경고는 기존 Next 프로젝트의 package type을 변경하지 않아 발생할 수 있다.

첫 명령은 브라우저가 생성한 실제 전송 패킷을 `.firmware-build/protocol-fixture.bin`에 기록한다. Visual Studio C++ 개발자 명령 프롬프트에서는 이어서 다음을 실행할 수 있다.

```bat
cl /nologo /EHsc /std:c++17 /utf-8 /W4 /Fe:.firmware-build\core-test.exe /Fo:.firmware-build\core-test.obj firmware\tests\core_test.cpp
.firmware-build\core-test.exe .firmware-build\protocol-fixture.bin .firmware-build\protocol-text.txt
```

보드용 컴파일:

```text
arduino-cli compile --fqbn esp32:esp32:esp32 --build-path .firmware-build/esp32 firmware/earlink
```

확인 결과: 웹 프로토콜 테스트 5건, TypeScript 검사, 웹 프로덕션 빌드, C++ 변환/분할/큐/시간/실제 패킷 재조립 테스트, ESP32 Dev Module 컴파일 통과. 한글 전체 순회 테스트는 셀 범위와 길이 검증이며 모든 음절의 점역 정답 검증은 아니다. 전체 ESLint에는 이번 변경 이전의 지문자 관련 오류 2건이 남아 있다. 실물 업로드·BLE 연결·점 위치·촉독·전원 안정성은 아직 검증하지 않았다.
